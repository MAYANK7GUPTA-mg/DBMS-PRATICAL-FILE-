# Experiment 6: Stored Procedure and Triggers

## Aim
To create a stored procedure for transferring an employee between departments, validate salaries using triggers, and record department changes in an audit table.

## Software
- MySQL
- A SQL client that supports stored procedures, triggers, and `DELIMITER`

## Database Design
The experiment uses a small, self-contained database with three tables:

| Table | Purpose |
|---|---|
| `department` | Stores department IDs and names |
| `employee` | Stores employee ID, name, department, and salary |
| `employee_audit` | Records employee department changes |

The script inserts **3 departments and 4 employees**. It drops and recreates these tables, so do not run it in a database containing data you need to keep.

## Procedure and Triggers

### 1. `validate_salary_insert`
A `BEFORE INSERT` trigger rejects a salary that is `NULL` or less than or equal to zero.

### 2. `validate_salary_update`
A `BEFORE UPDATE` trigger applies the same salary validation when an employee record is updated.

### 3. `employee_audit_update`
An `AFTER UPDATE` trigger adds an audit record whenever an employee's department changes.

### 4. `transfer_employee(emp_id, new_dept_id)`
The procedure checks that both IDs are supplied, the employee exists, the target department exists, and the employee is not already in that department. It then updates the employee's department. An SQL exception handler rolls back and re-raises errors.

## How to Run
1. Open `exp6.sql` in a MySQL-compatible client.
2. Run the script from the top.
3. Confirm that `CALL transfer_employee(101, 2);` completes.
4. Run the final two `SELECT` queries to inspect the employee table and audit log.
5. To test an expected error, uncomment **one** test at the bottom and run it separately.

> **ByteXL note:** Some browser SQL runners do not support `DELIMITER` or stored-program definitions. If ByteXL rejects the `CREATE TRIGGER` or `CREATE PROCEDURE` statements, use a MySQL client that supports stored programs, such as MySQL Workbench. Do not interpret printed trigger-definition text as the table output; use the final `SELECT` statements for the actual results.

## Expected Output

After the successful call `CALL transfer_employee(101, 2);`, employee 101 (Aman) should have `dept_id = 2`. The audit table should contain one row showing the change from department 1 to department 2.

### Employee table (key columns)

| emp_id | emp_name | dept_id | salary |
|---:|---|---:|---:|
| 101 | Aman | 2 | 25000.00 |
| 102 | Riya | 1 | 30000.00 |
| 103 | Rahul | 2 | 28000.00 |
| 104 | Neha | 3 | 22000.00 |

### Audit table (key columns)

| audit_id | emp_id | old_dept | new_dept |
|---:|---:|---:|---:|
| 1 | 101 | 1 | 2 |

The timestamp in `changed_at` is generated by MySQL and will vary.
